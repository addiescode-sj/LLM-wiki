# ADR-001: 개인 → 팀 지식 격상 정책

## 상태

`승인됨`

---

## 맥락 (Context)

LLM Wiki는 개인 지식 축적과 팀 공유를 분리하여 운영한다.
개인 브랜치(`personal/<이름>`)에서 먼저 지식의 품질을 검증한 뒤,
팀에게 가치 있는 내용만 `main` 브랜치로 격상한다.

이 ADR은 **어떤 지식이 격상할 가치가 있는가**, **어떤 절차로 격상하는가**를 정의한다.

---

## 격상 적합 기준 (Promotion Criteria)

### ✅ 격상 권장

| 기준 | 예시 |
|------|------|
| 팀 전체가 반복적으로 검색할 개념 | 시스템 아키텍처 결정, 공통 라이브러리 사용법 |
| 온보딩에 필요한 지식 | 배포 절차, 코드 컨벤션, 환경 설정 가이드 |
| 트러블슈팅 기록 | 프로덕션 인시던트 회고, 디버깅 노하우 |
| 팀 미팅/결정 사항 | 스프린트 회고, 기술 선택 ADR |
| 외부 기술 리서치 | 새 프레임워크 도입 검토, 벤치마크 결과 |

### ❌ 격상 불필요 (개인 브랜치 유지)

| 기준 | 예시 |
|------|------|
| 개인 학습 메모 | 개인 공부 노트, 책 요약 |
| 일시적 맥락 | 특정 PR 작업 중 임시 메모 |
| 미완성 초안 | 검증되지 않은 아이디어 |
| 개인 TODO | 내가 나중에 볼 액션 아이템 |

---

## 격상 절차

```
1. 개인 브랜치에서 지식 축적
   personal/<이름> 브랜치에서 raw/ 추가 → 자동 인입 → wiki/ 생성

2. 자가 검토 (Self-Review)
   ./scripts/lint.sh 통과 확인
   내용이 팀에게 실제로 유용한지 자문

3. PR 생성
   personal/<이름> → main PR 오픈
   .github/PULL_REQUEST_TEMPLATE.md 체크리스트 작성

4. 팀 리뷰 (최소 1인)
   리뷰어: 내용의 정확성 + 팀 관련성 확인
   승인 후 Squash Merge

5. 격상 완료
   main 브랜치에 반영 → 팀 전체 접근 가능
```

---

## 검토한 선택지

### 옵션 A: 모든 지식을 바로 main에 커밋
- **장점**: 절차 단순
- **단점**: 개인 실험/초안이 팀 위키를 오염시킴

### 옵션 B: 개인/팀 저장소 완전 분리
- **장점**: 완전한 격리
- **단점**: 지식 이동 마찰 높음, 관리 비용 2배

### 옵션 C: 브랜치로 분리, PR로 격상 ← **선택**
- **장점**: Git 워크플로우 자연스럽게 활용, 코드 리뷰 문화 이식
- **단점**: PR 생성 마찰 (체크리스트로 최소화)

---

## 결정

**선택**: 옵션 C — 브랜치 분리 + PR 격상

**이유**: 팀이 이미 코드 PR 리뷰 문화에 익숙하므로 동일한 워크플로우를 지식 관리에 적용하면 학습 비용이 최소화된다.

---

## 결과 및 영향

- 개인은 실험적 지식을 부담 없이 쌓을 수 있음
- 팀 위키(`main`)는 검증된 지식만 포함 → 신뢰도 유지
- PR 히스토리가 "왜 이 지식이 중요한가"의 맥락을 보존
